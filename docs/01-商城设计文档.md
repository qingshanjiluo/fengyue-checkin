### 1.3 代币经济模型

- 代币: users.balance（整数）
- 汇率: 1 元人民币 = `token_per_rmb` 代币（settings 表，默认 100）
- 账号定价: 由渠道配置自动计算 `price = floor(petals / unit) * price_per_unit`，单位代币
- 充值: 当前无在线支付，采用"套餐选择 + 联系 QQ 群人工充值"，管理员在后台 users/charge 充代币

## 3. 页面详细设计

### 3.1 首页 home

结构:
1. 顶部公告滚动栏（见 2.2）
2. 主视觉区: 醉翁亭名号 + 一句标语 + 两个按钮（进入账号市场 / 立即注册）
3. 数据面板（见 2.3）
4. 平台介绍卡片区: 4 个平台各一张卡（图标/中文名/一句话说明/该平台账号数+在售数）
5. 公告列表（完整公告标题+内容，时间）

依赖 API: GET /api/stats、GET /api/notifications

### 3.2 账号市场 market

功能:
- 顶部: 平台筛选（全部/春水酒馆/风月酒馆/密丝AI/DZMM），按平台分组或下拉筛选
- 商品卡片列表: 每张卡显示 平台名 / 昵称 / 积分(petals，带平台单位) / 售价(代币) / 注册时间 / 购买按钮
- 购买交互:
  - 未登录: 点击购买弹窗提示"请先登栈"
  - 已登录: 点击购买弹确认框（显示价格与余额），确认后 POST /api/orders，成功后弹"购得"印章动画并展示账号凭据（email/password），同时刷新余额
  - 余额不足: 弹窗提示代币不足，提供"去充值"按钮跳转 recharge
- 数据: GET /api/products（公开，现有返回含 id/nickname/petals/registered_at/price/platform）

平台单位映射:
```
PLATFORM_UNITS = { aimagnet:'花瓣', fengyue:'积分', missai:'体验点', dzmm:'积分' }
PLATFORM_LABELS = { aimagnet:'春水酒馆', fengyue:'风月酒馆', missai:'密丝AI', dzmm:'DZMM' }
```

### 3.3 用户中心 me

结构:
1. 用户信息卡: 用户名 / 角色 / 代币余额 / 汇率提示（1元=N代币）
2. 我的账号列表: 每行显示 昵称/平台/积分/注册时间/价格（购买价）/上次签到日期，展开显示凭据（email+password）
3. 交易记录: 最近 50 条（金额/类型/备注/时间），类型中文映射: charge=充值, buy=购买, admin=管理调整

依赖 API: GET /api/wallet（返回 balance/user/transactions）、GET /api/accounts/mine

### 3.4 充值/套餐 recharge

结构:
1. 汇率说明卡: "1 元 = {token_per_rmb} 代币，充值请添加 QQ 群：{群号}"
2. 套餐选择卡: 预置套餐表（金额/代币/赠送），点击"复制备注"生成充值备注文本（含用户 ID），引导用户联系管理员
   - 套餐数据: 前端内置常量 `RECHARGE_PACKAGES`，价格随 token_per_rmb 动态计算
3. 提示: "充值到账由管理员审核发放，可联系群内管理员"

QQ 群号: 需管理员配置，暂用前端常量 `QQ_GROUP`（阶段 2 可改为 settings 配置）

依赖 API: GET /api/stats（取 token_per_rmb）或 GET /api/admin/settings（公开版设置接口，阶段 1 用 stats 中的 token_per_rmb）

### 3.5 邀请 invite

结构:
1. 邀请说明卡: 说明邀请奖励规则（阶段 1 先展示文案，邀请关系表后端在阶段 1 预留）
2. 邀请码展示: 调用 GET /api/invite/code 获取用户专属邀请码
3. 复制邀请链接按钮: 链接为注册页带邀请码参数（商城无注册页，暂复制码文本，前端注册放 login 页）

后端阶段 1 新增:
- 表 invites(id, user_id, code, created_at) 或直接 users.invite_code 列
- GET /api/invite/code（登录）: 生成/返回用户邀请码
- POST /api/auth/register 增加可选 invite_code 字段，登记邀请关系（invite_relations 表）

奖励规则文案（阶段 1 静态展示）: 待产品确认，先写占位说明。

### 3.6 脚本皮肤市场 scripts

阶段 3 实现。占位页: 页面标题 + "敬请期待"说明。预留数据接口设计:
- 表 products(type='script'/'skin', name, desc, price, file_url, thumbnail)
- API: GET /api/products?type=script 等（与账号市场区分路径 /api/script-products）
- 购买下载: POST /api/script-orders

### 3.7 玩家市场 players

阶段 3 实现。占位页: 页面标题 + "敬请期待"说明。
数据模型待定（玩家发布/求购/交易），设计文档阶段 3 再细化。

### 3.8 聊天室 chat

阶段 4 实现。占位页: 页面标题 + "敬请期待"说明。
实现方案: D1 消息表 + 前端轮询（简单可靠），或 Worker WebSocket（需要额外配置）。阶段 4 决策。

### 3.9 管理员端

#### 3.9.1 号池监看 pool（现有，保留）
现有功能保持，补充 on_sale 状态筛选与上架账号查看。

#### 3.9.2 渠道管理 admin-channels
表格列出 channel_configs 全字段，支持行内编辑:
- enabled（开关）: 是否允许该渠道上架
- min_petals: 准入阈值
- unit / price_per_unit: 定价规则
- max_on_sale: 同时上架上限
按钮:
- "全池重新评估上架" -> POST /api/admin/channels/refresh
- 每行"保存" -> PATCH /api/admin/channels/:platform

#### 3.9.3 通知管理 admin-notices
- 新建通知表单（标题/内容/active）
- 通知列表（标题/内容/时间/active），支持停用/删除/编辑

#### 3.9.4 系统设置 admin-settings
- token_per_rmb 编辑 -> PATCH /api/admin/settings
- 显示汇率预览

```sql
-- 邀请奖励记录 (预留)
CREATE TABLE IF NOT EXISTS invite_relations (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  inviter_id INTEGER NOT NULL,
  invitee_id INTEGER NOT NULL,
  reward     INTEGER DEFAULT 0,
  created_at TEXT DEFAULT (datetime('now','localtime'))
);
```

## 5. 前端文件结构约定

单文件 SPA 内按区块组织（保持现有风格）:
```
// 1. 常量与配置 (API, PLATFORM_LABELS, PLATFORM_UNITS, RECHARGE_PACKAGES, QQ_GROUP)
// 2. 工具函数 (api, fmt, fmtTime, copy)
// 3. 图标组件
// 4. 公共组件 (Navbar, NoticeBar, StatCard, ProductCard, Stamp, Modal)
// 5. 页面组件 (HomePage, MarketPage, MePage, RechargePage, InvitePage,
//             ScriptsPage, PlayersPage, ChatPage, PoolAdminPage,
//             ChannelsAdminPage, NoticesAdminPage, SettingsAdminPage, LoginPage)
// 6. App 路由 (page 状态 + params, 登录保护)
```

页面切换沿用现有 page 状态 + setPage 模式；需要参数（如商品详情）用 pageParam 对象。

## 6. 验收标准（阶段 1）

1. 首页显示公告滚动栏、数据面板、平台卡片，数据来自 /api/stats 与 /api/notifications
2. 账号市场可按平台筛选、购买流程完整（确认/余额不足/成功展示凭据/刷新余额）
3. 用户中心展示余额、我的账号（含凭据展开）、交易记录
4. 充值页展示汇率与套餐，复制备注可用
5. 邀请页展示邀请码并支持复制
6. 管理员端可编辑渠道配置、全池上架、管理通知、改汇率
7. 未登录访问受保护页跳转登录页
8. 移动端布局可用
