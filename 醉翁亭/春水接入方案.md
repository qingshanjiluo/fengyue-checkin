# 醉翁亭 · 春水号池接入方案 (Cloudflare + GitHub Actions)

> 版本 v2.0 | 目标: 春水账号自动注册/签到 → 醉翁亭后台监控 → 代币购买
> 配套: 总架构.md (风月线) + 本方案 (春水线)

---

## 1. 目标与业务流

```
[GitHub Actions 定时]
   ├─ 注册 job   : 新注册 N 个春水号 → 上报 Worker → D1
   ├─ 签到 job   : 从 D1 拉账号 → 批量签到 + 同步花瓣 → 上报
   └─ 探活 job   : 登录检查账号可用性 → 更新 D1
          │  POST /api/chunshui/sync  (Bearer ADMIN_TOKEN)
          ▼
[Cloudflare Worker = 醉翁亭 API]
   ├─ 认证/用户 (JWT + KV 黑名单)
   ├─ 商品/订单/钱包 (代币)
   ├─ 春水账号管理 (admin 监控 / sync 接收)
   └─ D1 (SQLite 数据库)
          ▲
          │  GET /api/...  (JWT)
[Cloudflare Pages = 醉翁亭前端]
   ├─ 用户端: 浏览春水账号商品 → 代币购买 → 自动交付
   └─ 管理端: 号池监控 (可用性/花瓣/签到/注册时间/销量)
```

**关键链路**:
1. GitHub Actions 定时跑脚本（Python），直连 aimagnet.vip + mail.tm
2. 注册/签到/探活结果通过 Worker 同步 API 写入 D1
3. 醉翁亭后台从 D1 读取展示；用户用余额(代币)购买账号，下单扣款交付

## 2. D1 Schema 扩展 (在总架构.md 基础上)

```sql
-- accounts 表扩展 (增加 platform 维度)
ALTER TABLE accounts ADD COLUMN platform TEXT NOT NULL DEFAULT 'fengyue'; -- 'fengyue'|'chunshui'
ALTER TABLE accounts ADD COLUMN email_password TEXT;
ALTER TABLE accounts ADD COLUMN user_id TEXT;
ALTER TABLE accounts ADD COLUMN registered_at TEXT;   -- 春水注册时间 (unix 秒)
ALTER TABLE accounts ADD COLUMN petals INTEGER DEFAULT 0;  -- 春水花瓣
ALTER TABLE accounts ADD COLUMN last_sign_date TEXT;       -- 最近签到日
ALTER TABLE accounts ADD COLUMN last_sign_at TEXT;
ALTER TABLE accounts ADD COLUMN last_check_at TEXT;       -- 最近探活时间
ALTER TABLE accounts ADD COLUMN last_check_ok INTEGER DEFAULT 1; -- 可用性
ALTER TABLE accounts ADD COLUMN check_error TEXT;         -- 探活失败原因

-- 春水签到记录 (每日)
CREATE TABLE IF NOT EXISTS chunshui_sign_records (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id INTEGER NOT NULL,
  date       TEXT NOT NULL,
  status     TEXT NOT NULL,              -- SIGNED/ALREADY/ERROR
  reward     INTEGER,
  created_at TEXT DEFAULT (datetime('now','localtime')),
  UNIQUE(account_id, date)
);

-- 春水花瓣快照 (每日)
CREATE TABLE IF NOT EXISTS chunshui_point_snapshots (
  account_id INTEGER NOT NULL,
  date       TEXT NOT NULL,
  petals     INTEGER NOT NULL,
  UNIQUE(account_id, date)
);
```

索引:
```sql
CREATE INDEX idx_cs_account ON chunshui_sign_records(account_id, date);
CREATE INDEX idx_cs_point ON chunshui_point_snapshots(account_id, date);
CREATE INDEX idx_acc_platform ON accounts(platform, status);
```

## 3. Worker API 新增

### 3.1 同步端点 (GitHub Actions 调用, 需 ADMIN_TOKEN)
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/chunshui/sync` | 批量 upsert 账号 `{accounts:[{nickname,password,email,email_password,user_id,registered_at,petals,status}], sign_records:[...], snapshots:[...]}` |
| POST | `/api/chunshui/checkin` | 签到结果上报 `{account_id, date, status, reward}` |
| POST | `/api/chunshui/petals` | 花瓣快照上报 `{account_id, date, petals}` |
| POST | `/api/chunshui/health` | 探活结果 `{account_id, ok, error}` |

### 3.2 管理/展示端点 (需 admin JWT)
| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/admin/chunshui/accounts?status=&q=` | 号池列表(可用性/花瓣/签到/注册时间) |
| GET  | `/api/admin/chunshui/accounts/:id` | 详情 + 签到历史 + 花瓣走势 |
| GET  | `/api/admin/chunshui/stats` | 总览(总数/可用/失效/总花瓣/今日已签/待售) |
| POST | `/api/admin/chunshui/register` | 手动触发 GitHub Actions 注册(可经 workflow_dispatch) |

### 3.3 用户购买 (代币)
| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/products?type=chunshui&status=on` | 在售春水账号商品 |
| POST | `/api/orders` | 下单 `{product_id}` → 扣代币 → 分配账号 → 交付 |
| GET  | `/api/accounts/mine` | 我购买的账号(含凭证) |
| GET  | `/api/accounts/:id/records` | 账号签到/花瓣记录 |

> 复用总架构的 products/orders/users 表；商品挂 `platform='chunshui'` 的账号池。

## 4. GitHub Actions 设计

### 4.1 仓库结构
```
.repo/
├── .github/workflows/
│   ├── chunshui-register.yml   # 定时/手动注册
│   ├── chunshui-daily.yml      # 每日签到 + 花瓣 + 探活
├── scripts/
│   ├── chunshui_register.py    # 注册 (复用 chunshui_pool/chunshui.py)
│   ├── chunshui_daily.py       # 签到+花瓣+探活
│   └── chunshui_client.py      # 上报 Worker 客户端
```

### 4.2 Secrets
| Secret | 用途 |
|--------|------|
| `ZUIWENG_API` | Worker 地址 `https://zuiweng.xxx.workers.dev` |
| `ADMIN_TOKEN` | Worker 同步鉴权 |
| `COUNT_PER_RUN` | 每次注册数量(可配) |

### 4.3 注册 workflow
```yaml
name: chunshui-register
on:
  schedule: [{cron: '0 */3 * * *'}]   # 每 3 小时 60 个
  workflow_dispatch: {inputs: {count: {type: number, default: 20}}}
jobs:
  register:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: '3.10'}
      - run: pip install requests
      - run: python scripts/chunshui_register.py --count ${{ inputs.count || 20 }}
        env:
          ZUIWENG_API: ${{ secrets.ZUIWENG_API }}
          ADMIN_TOKEN: ${{ secrets.ADMIN_TOKEN }}
```
> 脚本内: 串行注册(20s/IP 冷却) → 完成后批量 POST /api/chunshui/sync。

### 4.4 每日 workflow (签到+花瓣+探活)
```yaml
name: chunshui-daily
on:
  schedule: [{cron: '10 0 * * *'}]   # 每日 08:10 北京
jobs:
  daily:
    runs-on: ubuntu-latest
    steps:
      - ...checkout/setup-python/pip install...
      - run: python scripts/chunshui_daily.py
        env: {ZUIWENG_API, ADMIN_TOKEN}
```
> 脚本内: GET 号池(经 Worker) → 逐个 login→signin→balance → POST 结果。

## 5. 关键风险与 PoC (必做)

### 5.1 GitHub Actions 出口 IP
- GitHub runner = Azure 数据中心 IP，aimagnet 的 Cloudflare 可能直接拦截
  (本地已验证: XFF 伪造被拦、curl_cffi 指纹被识、datacenter IP 风险高)
- **P0 必须 PoC**: 提交一个 workflow 调 aimagnet GET 探活 + mail.tm 建邮箱，
  验证 runner IP 是否被 aimagnet 接受。
- 若被拦 → 备选:
  a. **self-hosted runner** 挂用户本机(走 Clash 家庭 IP)
  b. workflow 内走第三方代理(需代理池/服务器)
  c. 注册留在本机 cron，仅签到/探活放 Actions(同样受 IP 限制)

### 5.2 账号凭据安全
- 密码/邮箱密码会经 Worker sync 写入 D1(明文)。D1 是 Cloudflare 托管数据库，
  与 worker secret 同级保护；管理端二次校验后展示。
- GitHub Secrets 只存 API 地址 + token，不存账号密码(账号密码在 D1 由 Actions 回拉)。

### 5.3 并发与限速
- 注册串行 20s/IP; 若多 IP runner 并行 → 每 runner 独立计数。
- 签到/登录也有 Cloudflare 限流(实测 429) → 脚本内退避重试。
