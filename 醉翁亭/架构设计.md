# 醉翁亭 · 风月账号交易与托管平台 架构设计

> 版本 v1.0 | 部署目标：Cloudflare (Pages + Workers + D1 + Cron + KV)
> 业务：风月平台账号售卖 + 月度托管（代签/代抽奖）

---

## 1. 业务概述

### 1.1 业务模式

| 产品类型 | 说明 | 计价 |
|---------|------|------|
| **账号售卖** | 自动注册风月账号，作为商品出售，交付账号密码 + JWT | 一次性买断 |
| **账号托管** | 按月订阅，平台每日代签 + 代抽奖，产出归用户 | 按月包月 |
| **角色卡/内容** | （扩展）风月角色卡定制、代发等增值服务 | 按需 |

### 1.2 核心角色

- **游客**：浏览商品、注册/登录
- **用户（顾客）**：购买账号、开通托管、查看名下账号与抽奖记录
- **管理员**：商品管理、批量注册、账号库存管理、托管开通/续费、手动触发任务、数据总览

### 1.3 关键业务流程

```
【账号售卖】管理员批量注册 → 账号入库(库存池) → 上架商品 → 用户下单
            → 支付确认 → 自动交付(账号+密码+JWT) → 商品下架

【账号托管】用户购买托管套餐 → 绑定/分配账号 → 每日 Cron 定时执行
            → 签到 + 抽奖 → 结果入库 → 用户前台查看记录 → 到期自动续费/停用

【自动注册】管理员触发 /api/admin/register → Worker 调风月平台注册接口
            → 滑块破解 → 批量入库 → 库存池
```

### 2.2 部署组件

| 组件 | 用途 | Cloudflare 产品 |
|------|------|----------------|
| 前端 SPA | 用户端 + 管理端界面 | **Pages** |
| API 服务 | 全部业务逻辑与风月平台交互 | **Workers**（路由 `/api/*`）|
| 数据库 | 用户/商品/账号/订单/托管/记录 | **D1** (SQLite) |
| 会话存储 | JWT 黑名单、限流、临时状态 | **KV** |
| 定时任务 | 每日签到+抽奖 | **Cron Trigger**（Worker 内）|
| 密钥管理 | 风月 API Key、平台账号等 | **Workers Secrets** |
| 网关 | 域名绑定 / WAF / 限速 | **Cloudflare Zone** |

### 2.3 技术选型说明

- **前端**：保留现有 `醉翁亭.html` 的 React SPA + Tailwind 风格，去掉 mock 数据，接入真实 API。
- **后端**：Workers 使用 TypeScript/JavaScript，用 `fetch` 直连风月平台（复用现有 Python 脚本中的 API 端点与多域名容错逻辑）。
- **数据库**：D1 原生 SQLite，支持 JOIN，适合订单/账号/记录这类关系型数据。
- **定时任务**：Workers Cron Trigger，本地兼容验证（`wrangler dev --test-scheduled`）。
- **支付**：抽象支付适配层，先接「手动转账/客服确认」模式（管理员后台确认到账），预留微信/支付宝/虚拟币网关扩展位。

## 3. 数据模型 (D1 Schema)

```sql
-- 用户表
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT NOT NULL UNIQUE,
  password_hash  TEXT NOT NULL,              -- PBKDF2/Argon2
  role          TEXT NOT NULL DEFAULT 'user', -- 'user' | 'admin'
  balance       INTEGER NOT NULL DEFAULT 0,   -- 余额(分)
  created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- 商品表
CREATE TABLE products (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  type          TEXT NOT NULL,               -- 'account' | 'hosting' | 'service'
  title         TEXT NOT NULL,
  description   TEXT NOT NULL DEFAULT '',
  price         INTEGER NOT NULL,            -- 单位:分
  period_days   INTEGER,                     -- 托管有效天数(月=30)
  status        TEXT NOT NULL DEFAULT 'on',  -- 'on' | 'off'
  stock         INTEGER NOT NULL DEFAULT 0,  -- 可用库存
  created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- 风月账号表（平台侧账号）
CREATE TABLE accounts (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  name          TEXT NOT NULL,
  password      TEXT NOT NULL,               -- 平台账号密码
  email         TEXT NOT NULL DEFAULT '',
  jwt           TEXT NOT NULL,               -- 风月平台 JWT (敏感)
  points        INTEGER NOT NULL DEFAULT 0,  -- 当前积分(定期同步)
  status        TEXT NOT NULL DEFAULT 'pool',
                -- 'pool'(库存池) | 'sold'(已售) | 'hosting'(托管中) | 'disabled'(停用)
  product_id    INTEGER REFERENCES products(id),
  owner_id      INTEGER REFERENCES users(id),
  expires_at    TEXT,                        -- 托管到期时间
  created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- 订单表
CREATE TABLE orders (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  order_no      TEXT NOT NULL UNIQUE,        -- 订单号
  user_id       INTEGER NOT NULL REFERENCES users(id),
  product_id    INTEGER NOT NULL REFERENCES products(id),
  account_id    INTEGER REFERENCES accounts(id),
  amount        INTEGER NOT NULL,            -- 金额(分)
  status        TEXT NOT NULL DEFAULT 'pending',
                -- 'pending' | 'paid' | 'delivered' | 'cancelled'
  created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  paid_at       TEXT
);

-- 托管订阅表
CREATE TABLE subscriptions (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  order_id      INTEGER REFERENCES orders(id),
  user_id       INTEGER NOT NULL REFERENCES users(id),
  account_id    INTEGER NOT NULL REFERENCES accounts(id),
  start_date    TEXT NOT NULL,
  end_date      TEXT NOT NULL,
  status        TEXT NOT NULL DEFAULT 'active', -- 'active' | 'expired' | 'cancelled'
  auto_renew    INTEGER NOT NULL DEFAULT 1
);

-- 签到记录表
CREATE TABLE sign_records (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id    INTEGER NOT NULL REFERENCES accounts(id),
  date          TEXT NOT NULL,               -- YYYY-MM-DD
  status        TEXT NOT NULL,               -- 'SIGNED' | 'SKIP' | 'ERROR'
  reward        TEXT,
  created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  UNIQUE(account_id, date)
);

-- 抽奖记录表
CREATE TABLE lottery_records (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id    INTEGER NOT NULL REFERENCES accounts(id),
  date          TEXT NOT NULL,
  status        TEXT NOT NULL,               -- 'WIN' | 'BIG' | 'SKIP' | 'ERROR'
  prize         TEXT,
  amount        INTEGER,
  created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  UNIQUE(account_id, date)
);

-- 设置表（平台配置）
CREATE TABLE settings (
  key           TEXT PRIMARY KEY,
  value         TEXT NOT NULL
);
```

**索引建议**：
```sql
CREATE INDEX idx_accounts_status ON accounts(status);
CREATE INDEX idx_orders_user ON orders(user_id, created_at);
CREATE INDEX idx_records_account ON lottery_records(account_id, date);
CREATE INDEX idx_sub_active ON subscriptions(account_id, status);
```

## 5. 风月平台集成层（核心逻辑移植）

> 复用现有 `签到+抽奖.py` / `无绑定账号注册.py` 的 API 端点与容错策略，用 JS 在 Worker 内重写。

### 5.1 常量与容错
```js
const BASE = "https://ai-xan.xyz";
const BACKUP_DOMAINS = ["https://acepro.store", "https://acquainte.xyz",
  "https://acquant.xyz", "https://affectional.xyz", "https://aiwhatis.xyz",
  "https://aquantancee.xyz", "https://aigirlfriend.baby"];
```
- 每个请求对域名列表**逐个尝试**，空响应/异常立即换下一个。
- 携带 `User-Agent`（Chrome 126 桌面 UA），防 Cloudflare 拦截。

### 5.2 接口封装
| 功能 | 端点 | 说明 |
|------|------|------|
| 查积分 | `GET  /go/api/account/point` | 返回 `data.points` |
| 签到 | `GET  /console/api/sign_in` | code=200 为成功 |
| 抽奖 | `POST /console/api/daily_lottery/draw` | body `{}` |
| 注册 | `GET /go/api/slide/get` → 滑块破解 → `POST /console/api/register` | 见下 |
| 滑块破解 | `POST /go/api/slide/check` body `{id, point:"x,y"}` | 扫 x:0-300 步进 20 |

### 5.3 每日调度器 (Cron Trigger)
```
Cron 表达式: 5 0 * * *   (UTC 00:05 = 北京 08:05)
流程:
1. 读 D1: SELECT * FROM accounts WHERE status='hosting' OR status='pool'
   （hosting 必须跑；pool 也跑以便展示积分）
2. 对每个账号: 查积分 → 签到 → 抽奖
3. 结果写入 sign_records / lottery_records
4. 大奖(≥5万积分或月卡) 记录到设置表/通知
5. 更新 accounts.points
6. 失败账号重试 2 轮
```
> **并发限制**：逐账号串行 + 间隔，避免触发风控。账号多时可用 `Promise.all` 分批(每批3个)。

### 5.4 自动注册任务
```
POST /api/admin/register {count: 10}
1. 生成随机用户名 u[0-9a-z]{10}, 密码 Kilo[A-Za-z0-9]{6}1
2. 首页 GET 取 cookie → GET /go/api/slide/get 拿滑块参数
3. 滑块破解: POST /go/api/slide/check 扫 x(0-300,步20), code=100000 通过
4. POST /console/api/register {name,password,code:"",client,interface_language,reg_token}
5. 成功 → jwt 入库 accounts(status='pool')
6. 失败(频繁) → 退避 15s 重试；最后汇总报告
```

## 6. 定时任务与通知

| 任务 | 触发 | 逻辑 |
|------|------|------|
| 每日签到抽奖 | Cron `5 0 * * *` | 见 §5.3 |
| 托管到期检查 | Cron `30 0 * * *` | `expires_at < now` → 状态改 expired，邮件/站内提醒 |
| 库存补货提醒 | Cron `0 9 * * *` | 库存低于阈值 → 管理员通知 |
| 数据备份 | Cron `0 3 * * 0` | D1 导出备份 |

> 通知方式扩展位：Webhook（如 Server 酱 / Telegram Bot）——见 settings 表 `notify_webhook`。

## 7. 安全设计

| 项 | 方案 |
|----|------|
| 用户密码 | Workers 原生 WebCrypto PBKDF2 (10万次迭代) |
| 会话 | JWT (HS256)，签名密钥存 KV Secret；登出进 KV 黑名单 |
| 权限 | JWT role 字段 + 管理端路由二次校验 |
| 风月 JWT | 存 D1（加密列待扩展），仅管理端/交付时解密展示 |
| 输入校验 | 所有字段长度/类型校验，SQL 一律参数化 (PreparedStatement) |
| 限流 | KV 滑动窗口限流（登录 5次/分，下单 10次/分）|
| CORS | Pages 同域部署 + 明确 Origin 白名单 |
| 管理端 | 额外二次密码或邮箱验证码（设置表可配）|

## 11. 待确认决策点

1. **支付方式**：先做「余额 + 管理员确认到账」，还是直接接第三方支付（需企业资质）？
2. **风月账号交付形式**：前端直接显示账号密码+JWT，还是只显示账号密码（JWT 单独提供）？
3. **抽奖产出分配**：托管产出的积分全部归用户，还是平台抽成？（当前设计：归用户）
4. **注册并发**：默认并发 8（同现有脚本），是否需要代理池配置？
5. **域名**：是否已有独立域名绑定到 Cloudflare？Pages 默认提供 `*.pages.dev` 子域。
