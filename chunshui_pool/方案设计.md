# 春水池 · 春水号池管理面板 架构设计

> 版本 v1.0 | 部署目标：Cloudflare (Pages + Workers + D1 + Cron + KV)
> 业务：春水(aimagnet.vip) 账号号池管理，查看注册时间 / 签到时间 / 积分(花瓣)

---

## 1. 业务概述

### 1.1 目标
维护一批春水(aimagnet.vip / 春水Live)注册账号的号池，提供：
- **注册时间**：账号何时注册（导入/注册入库时间）
- **签到时间**：每日是否签到、最近签到时间、签到历史
- **积分**：当前花瓣余额、历史余额走势

### 1.2 核心角色
- **管理员**：查看号池、手动/定时签到、同步积分、增删账号
- **系统(Cron)**：每日自动签到全部账号 + 定时同步积分快照

## 3. 数据模型 (D1 Schema)

```sql
-- 春水账号表
CREATE TABLE accounts (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  nickname     TEXT NOT NULL,               -- 网名
  password     TEXT NOT NULL,               -- 春水登录密码(明文, 平台需要)
  email        TEXT NOT NULL,               -- 注册邮箱
  email_password TEXT,                      -- 邮箱密码(mail.tm/Cloud Mail)
  user_id      TEXT,                        -- 春水 user_id
  points       INTEGER NOT NULL DEFAULT 0,  -- 花瓣余额(定期同步)
  status       TEXT NOT NULL DEFAULT 'active', -- 'active'|'disabled'
  imported_at  TEXT NOT NULL DEFAULT (datetime('now','localtime')), -- 入库时间
  registered_at TEXT,                       -- 注册时间(待确认来源, 见§8)
  last_sign_date TEXT,                      -- 最近签到日 YYYY-MM-DD
  last_sign_at   TEXT,                      -- 最近签到时间
  last_sync_at   TEXT,                      -- 最近积分同步时间
  UNIQUE(email)
);

-- 签到记录表
CREATE TABLE sign_records (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id INTEGER NOT NULL REFERENCES accounts(id),
  date       TEXT NOT NULL,                 -- YYYY-MM-DD
  status     TEXT NOT NULL,                 -- 'SIGNED'|'ALREADY'|'ERROR'
  reward     INTEGER,                       -- 本次奖励花瓣
  error      TEXT,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  UNIQUE(account_id, date)
);

-- 积分快照表 (每日)
CREATE TABLE point_snapshots (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id INTEGER NOT NULL REFERENCES accounts(id),
  date       TEXT NOT NULL,
  points     INTEGER NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  UNIQUE(account_id, date)
);

CREATE INDEX idx_sign_account ON sign_records(account_id, date);
CREATE INDEX idx_point_account ON point_snapshots(account_id, date);
```

## 4. API 设计 (全部需 Bearer ADMIN_TOKEN)

### 4.1 号池
| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/accounts?q=&status=` | 列表：网名/邮箱/积分/注册时间/最近签到/今日状态 |
| GET  | `/api/accounts/:id` | 详情 + 签到历史 + 积分走势 |
| GET  | `/api/stats` | 总览：总数/今日已签/待签/花瓣总额/签到率 |
| POST | `/api/accounts` | 手工添加账号 `{nickname,password,email,...}` |

| DELETE | `/api/accounts/:id` | 删除 |

| POST | `/api/sync/points` | 手动触发积分同步 |

## 5. 春水集成层 (chunshui.js)

> 复用本地 Python 脚本已探明的接口，JS 重写。

### 5.1 已确认接口
| 功能 | 端点 | 说明 |
|------|------|------|
| 登录 | `POST /v1/auth/login` body `{identifier:email, password}` | 返回 `data.tokens.accessToken` |
| 签到状态 | `GET /v1/users/signin/status` | `todaySigned / monthlyDays / signinDates` |
| 签到 | `POST /v1/users/signin` | 返回 `{petalsGranted:"200", monthlyDays}` |

### 5.2 待探测接口 (§8)
| 功能 | 猜测端点 | 说明 |
|------|------|------|
| 花瓣余额 | `GET /v1/me` / `/v1/wallet` / login user 对象 | 签到面板余额 50,000 的来源 |
| 注册时间 | login 响应 `user.createdAt` | 若 user 对象含时间戳 |

### 5.3 请求要点
```js
// Worker 内 fetch 直连
const HEADERS = {
  "user-agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/150.0.0.0 Safari/537.36",
  "origin": "https://aimagnet.vip",
  "referer": "https://aimagnet.vip/",
  "content-type": "application/json",
  "accept": "application/json",
};
// 认证: authorization: Bearer <accessToken>
```

### 5.4 关键风险：IP 风控
- 春水按出口 IP 风控：`register/start` 每 IP 20s 冷却、`ip_daily_cap` 每日上限
- **Worker 出口 IP 是 Cloudflare 数据中心 IP**，多个账号共享：
  - 签到/登录是否同样限速？**需 PoC 验证**（同一 Worker 连续登录多个账号）
  - 若受限 → 串行 + 每个账号间隔 ≥20s；每天 N 个账号需 N×20s
- **Cloudflare bot 检测**：Worker fetch 的 TLS 指纹/UA 可能被 aimagnet 的 Cloudflare 拦截（本地已证明 curl_cffi 被拒、XFF 被拦、datacenter IP 风险高）
  - → **P0 首要任务：PoC 测试 Worker 能否直连 aimagnet 登录/签到成功**

## 6. 定时任务 (Cron Trigger)

| 任务 | 触发 | 逻辑 |
|------|------|------|
| 每日签到 | Cron `10 0 * * *` (北京 08:10) | 逐个账号 login → signin/status → 未签则 signin → 写 sign_records → 更新 last_sign_*/points |
| 积分快照 | Cron `30 0 * * *` (北京 08:30) | login → 查余额 → 写 point_snapshots |
| 失败重试 | 签到任务内 | 单账号失败重试 1 次，仍失败记 ERROR |

> **并发**：账号多时按 每批 1-3 个 + 间隔分批，避免触发风控（PoC 后定具体节流值）。

## 8. 待确认决策点 / 待探测项

1. **注册时间来源**：春水 login 响应 `user` 对象是否含 `createdAt`？（本地脚本暂未打印该字段，代理恢复后探测）否则以本地 `imported_at` 作为注册时间展示。
2. **花瓣余额接口**：探测 `GET /v1/me`、`/v1/wallet`、login user 字段；确认后填入 §5.2。
3. **Worker 直连可行性（P0）**：部署最小 Worker，用同一出口登录 2-3 个账号，验证是否被风控/拦截。若 datacenter IP 被拒 → 备选：本机 Python 跑签到 + 结果上报 Worker API（Worker 只做展示层），或 Worker 用账号代理出口（不支持）。
4. **签到并发策略**：PoC 测出 登录/签到 的 IP 限速值，确定 Cron 每批数量与间隔。
5. **账号量级**：当前 ~9 个，若扩到 500+，签到总时长 = 账号数 × 每账号耗时（登录+签到 ≈ 2-3s，限速下 20s/个 → 500 个 ≈ 2.8 小时）。Cron 最小时钟粒度限制（Cron Trigger 至少每分钟 1 次，无长任务限制但受 Worker CPU 时间限制）→ 大号池时需分片多 Cron 或 worker 队列。
6. **自动注册**：是否要 Worker 内自动注册新号（复用本地脚本逻辑）？注册比签到更敏感（20s/IP 冷却 + mail.tm 限速 + Worker datacenter IP），建议先不做或本机批量注册后导入。

## 11. 安全设计

| 项 | 方案 |
|----|------|
| API 认证 | `Authorization: Bearer <ADMIN_TOKEN>`（Workers Secret）|
| 账号密码 | 春水密码为平台凭证，D1 明文存储（风险标注：D1 数据与 Secret 同级保护）；邮箱密码同 |
| 限流 | KV 滑动窗口：管理 API 10 次/分 |
| CORS | 仅允许本 Pages 域名 |
| 风控 | 春水交互串行限速，失败退避，避免触发 ip_daily_cap |
